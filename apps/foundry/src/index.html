NeoSmartUI is the AI-first neo-brutalist UI system. This Foundry is the public proof surface for one canonical architecture: Components → Blocks → Pages → Applications.

v0.2 Core

The Foundry exercises generic Core primitives through one resolved Rivet Light Theme and adapter-owned rendering boundaries. Public-proof maturity remains separately gated on deployed evidence.

Public-proof component: core.button

core.button is rendered through the Web adapter using resolved semantic tokens. Hover compresses into the surface; press seats the control instead of lifting it.

Public-proof component: core.checkbox

The native checkbox remains the semantic control. A 44px token-backed hit target contains the smaller visual box, with checked and indeterminate state remaining distinct after contact feedback ends.

Public-proof component: core.input

The native text input owns editing and selection. It is interactive, not pressable: hover, focus, and pointer contact never translate the field or simulate button compression.

Public-proof component: core.radio

Native radios preserve one-of-many selection and platform keyboard behavior. Contact compresses into the surface while checked state remains explicit across the whole group.

Public-proof component: core.switch

A native checkbox base exposes switch semantics while checked state stays authoritative. Contact compresses the whole track; persistent state moves the thumb from logical inline-start to inline-end as track color resolves.

Public-proof component: core.tabs

Tabs are a composite widget: roving focus, selected panel, and activation mode remain explicit. Selected tabs stay seated in their rail instead of rising above their peers.

Public-proof component: core.textarea

The native multiline textarea preserves line breaks, selection, scrolling, IME, and resize behavior. It is interactive, not pressable: editing and resize contact never borrow button compression.

Public-proof component: core.select

The native single-select owns its option picker and keyboard behavior. Only the collapsed choice trigger receives pressure feedback; NeoSmartUI does not replace the browser/OS option popup.

Implemented component: core.card

The generic Card groups information without inventing activation. Its resting depth is structural and remains unchanged on hover or pointer contact.

Implemented component: core.badge

Badges communicate compact metadata or status without manufacturing activation or a live region. Tone supports the visible text instead of replacing meaning with color.

Implemented component: core.alert

Alerts are stable message surfaces, not implicit live regions. Tone supports explicit written meaning; announcement urgency remains a composition decision.

Implemented component: core.field

Field composes one real control with its label, help, and validation relationships. The container is not a group, action, or live region; semantics stay on the actual control and associated text.

Implemented component: core.breadcrumb

Breadcrumb exposes a real ordered location hierarchy. Ancestor locations stay native links, separators and passive ellipsis are presentation-only, and the current page is non-interactive text with aria-current="page".

Implemented component: core.pagination

Pagination keeps page destinations as native links with 44px tactile targets. The current page is non-interactive text with aria-current="page", unavailable boundaries stay non-operable, and passive ellipsis never becomes a fake control.

Implemented component: core.segmented-control

Segmented Control chooses one peer mode with real buttons and persistent aria-pressed state. It keeps normal Tab, Space, and Enter button behavior; it does not borrow Tabs roving focus or form-value Radio semantics.

Implemented component: core.tooltip

Tooltip keeps supplemental descriptions non-interactive: keyboard focus remains on the described target, Escape dismisses the surface, and reveal never moves the target.

Implemented component: core.combobox

Editable single-selection Combobox keeps query text separate from committed selection. DOM focus stays on the editable control while active suggestions move through aria-activedescendant; only the separate disclosure trigger uses tactile compression.

Implemented component: core.accordion

Accordion discloses related content with real buttons and ordinary document focus. Space and Enter use native button activation; Arrow/Home/End keys are not remapped into Tabs-style roving focus.
